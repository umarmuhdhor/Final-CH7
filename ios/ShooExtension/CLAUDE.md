# ShooExtension — owner: lead

Safari Web Extension (EX-01 … EX-08). Swift handler + web files in `Resources/`.

- `Resources/detector.js` is GENERATED from `detector/` (Team AI). Never edit it here — run `detector/scripts/sync-to-extension.sh`.
- Content scripts can't use ES `import`. Every script in `manifest.json > content_scripts.js` shares one global scope, loaded in order.
- Page data sent anywhere must follow contracts/ (PageSnapshot, ScanResult). Never send typed input values.
- Native messages (`sendNativeMessage`) are defined in contracts/app-group-keys.md.
- Script order: `dom.js` → `lists-client.js` → `detector.js` → `pipeline.js` → `thresholds-client.js` → UI scripts (`pill.js`, `gauge.js`, `popup.js`, `marks.js`, `replica.js`, `report.js`, `block.js`) → `snapshot.js` → `content.js` (last).
- Pages can shadow `document` and `<form>` properties with named elements (`<form name="querySelectorAll">`, DOM clobbering; isolated worlds share the DOM). Read documents and forms through `ShooDom` (`dom.js`: `all`, `one`, `forms`, `attr`, `root`, …), never `document.x` / `form.x` directly. `takeSnapshot` reads each part separately so `url`/`domain` (layer 1) always get through, and block.js never waits on a failed report (≤ 1.2 s).
- Warning UI vs the page (30–79): hosts (`shoo-live-score`, `shoo-warning`, `shoo-marks`) are mounted with `ShooDom.guard(host, root)`: inline `all: initial !important`, page-added attributes removed, re-appended if removed, max 20 repairs; call the returned `release()` before removing a host on purpose. Document-level listeners ignore `!event.isTrusted`. Best effort only; the block screen (≥80) is the guarantee.
- C1 (#75): `snapshot.js` reads forms of the page plus up to 5 same-origin iframes (`contentDocument`), from the top frame only. No `all_frames`: the pipeline and UI run once per page. Cross-origin iframes are not read (Phase 2).
- Block memory (#231): `block-memory.js` (background) keeps every page blocked on this phone in `storage.local` for 14 days (max 500, oldest dropped), with its score, top 3 reasons (no `evidence`) and the backend scan id. Key: registrable domain, except on shared platforms (`SHARED`: a subdomain → full host, the platform host itself → host + path), so one scam on `sites.google.com` never blocks `google.com`. `runScan` asks it first (`recallBlock`): remembered → one fresh `GET /verdicts`; `safe` opens the page, anything else blocks at once with `remembered: true`, no layer run (no `/analyze`, so no LLM call) and no second report. Verdicts are per link (#241): every lookup sends the page URL (`GET /verdicts?url=&domain=`, `shareableUrl`), and a `safe` opens that link only; the domain's memory stays, so other pages of the site still ask first. Only the old per-domain lookup (no URL) clears the domain's entries. A link marked safe shows "Ditandai aman oleh <Guardian>" in the bubble instead of a score (#369). `block.js` sends `rememberBlock` before leaving the page (waits ≤ 300 ms).
- Block screen (EX-06) is the extension page `blocked.html` (listed in `web_accessible_resources`), not an overlay — page scripts can't remove it. Data travels in the URL fragment (`ShooBlock.encode/decode`). UI listens with `ShooPipeline.subscribe(state => …)`.
- EX-07: `report.js` sends one result per page (blocked, or warning once all layers are done). Evidence is a **page replica**, not a screenshot (contracts/api.md "Page replica"): `replica.js` serializes the DOM synchronously the moment `report.js` reports, before block.js leaves the page. Static only: no script/noscript/handlers/`javascript:`, frames/media/embeds become grey boxes, links become `href="#"` + `data-shoo-href` (origin + path), form `action` dropped, our `shoo-*` hosts left out, open shadow roots become `<template shadowrootmode="open">`. Typed input never goes in: no `<input value>` (except submit/button/reset labels), empty `<textarea>`, `input`/`select`/`textarea` keep only look attributes (`FIELD_ATTRS`: no `data-*`/`aria-*`/`title`, a script can mirror typed text there), editable areas (`[contenteditable]` except `false`, `[role=textbox|searchbox|combobox]`) emptied, empty `<body>` under `designMode`. The meta is spliced in with a replacer function (`$&` in a URL). Nodes are read through the prototypes (a form can clobber `attributes`/`childNodes`). Stylesheets (from `cssRules`, so CSS-in-JS rules count) and images are tokens; `background.js` finishes them with `replica-build.js` (cross-origin sheets and `@import` fetched, small images inlined as `data:` within the size budget, fonts and other loads removed), gzips + base64s it, and POSTs `pageReplicaBase64` with the scan. Too big → again without images, then without CSS, then no replica. `head` starts with charset + CSP + viewport + `shoo-replica` metadata (`focusY` = where the app scrolls first; `marks` = where each signal sits, #176: `report.js` `signalMarks` measures text evidence / logo `alt` / `asks_*` fields in document px when it reports, `replica.js` `cleanMarks` keeps what the app accepts; a failing lookup sends the replica without marks). ADM-07 evidence fragments (contracts/api.md "Evidence fragments"): `report.js` `fragmentGroups` picks the element behind each signal (field → its `<form>`, text → its block), `replica.js` `captureFragments` serializes only those (nested parts merged, the page's stylesheets once in `<head>`), `replica-build.js` `buildFragments` finishes them like the replica and `background.js` POSTs `evidenceFragmentsBase64` with every report, family or not (`413` → again without it, then without the replica).
- Layer 1 (docs/design/blocklist.md): `lists.js` in background downloads `/blocklist` + `/public-blocklist` into `storage.local` (hourly / 6 h / full daily, alarms); `lists-client.js` gives content scripts `ShooLists.match(hostname)`. The visited URL never leaves the phone.
- Thresholds (dashboard 05b X1, Safari only): `thresholds.js` (background) reads `GET /config/public` hourly into `storage.local` (last good value kept, 7 days max, else built-in 30/50/80); `thresholds-client.js` asks it (`thresholds` message, numbers only) and writes `ShooPipeline.THRESHOLD`. `secondWarning` (popup tier 2, not a setting) = 50, or the middle of the warning band when `warnAt` ≥ 50 so tier 1 never disappears. Not in `chrome/scripts/shared-files.txt`: Chrome keeps the built-in values. `thresholdsVersion` (the version `thresholds-client.js` stored on `THRESHOLD`) goes with each `POST /scans` from `report.js`; on a `422` background sends the scan again without it.
- EX-01: `heartbeat.js` (background) sends `{ type: "heartbeat", allSites }`; `allSites` = `browser.permissions.contains(*://*/*)`. Never `<all_urls>`: Safari's "Allow" on every website grants `*://*/*`, which WebKit doesn't count as covering `<all_urls>`, so it read false with full access. Sent from content scripts (throttled 1/min), on permission change (forced) and on the hourly alarm.
- C11: `last-seen.js` (background) rides along with the heartbeat: `PATCH /devices/me { extensionLastSeenAt }` max 1×/hour, last send kept in `storage.local`. Not onboarded → nothing sent; failure → retried next heartbeat.
- PF-01 (#183): `report.js` sends `pageChecked` once per page (`stats.checked`, a number only). `share-settings.js` decides what `startReport` sends: `blocked` always, `warning` only with `autoSend` and `shareWarnings` on. The switches arrive with `getSession`, so a change takes effect within `SESSION_TTL_MS` (30 s).
- EX-08: `marks.js` shows one reason bubble on tap. Highlights have no element, so taps (`pointerdown`/`pointerup` on `document`, never cancelled) are hit-tested against the stored ranges; a struck field's label is a button. Text: only `TEXT_SIGNALS` (`urgent_language`, `brand_logo_offsite`, `unreasonable_request`, `hoax_claim`) are highlighted, and `reasonFor` picks the heaviest of them quoting the phrase (a new text signal must be added there, #74); field: `asks_*` by name/id, else `asks_<kind>`, else `mark_why_<kind>`.
- EX-03 Dynamic Island (path C, #49): `live-island.js` (content) reports the page on screen to background (`liveScore`: `open`, `hostname`, `score`, `status`, `analyzing`); hidden tab / pagehide → `open: false`, bfcache `pageshow` → again. `live.js` (background) turns it into `POST /live` (contracts/api.md "Live score"): only with the online check on (`aiBaseURL` in getSession), registrable domain only (no IP/localhost), new page / status / analyzing change at once, score-only changes max 1 per second, `open: false` after 1.5 s unless another page comes on screen (tab switch). Domain and score are forwarded by the backend, never stored. Not in Chrome.
- EX-03 live score: the bubble (`pill.js`) stays on screen for the whole page at any score (hidden only when blocked or after Hide). `content.js` re-checks a settled page when its DOM changes (quiet 1.5 s, max 1 per 8 s, 6 per page, skipped if title/forms/images/text-length bucket are unchanged). A re-check passes `previous` to `runScan`: earlier signals are kept so the score only climbs, layer 3–4 always run again (layer 1–2 only read the domain), and nothing is published unless a layer finds a new or heavier signal. Same `scanId`, so report/block/popup treat it as the same page.
- #270: `/analyze` may answer `rdapRegisteredAt`; `runScan` keeps it on the state (a re-check with no date keeps the earlier one) and `report.js` `scanBody` copies it into `POST /scans`. A page blocked by layer 1–2 is reported before `/analyze` answers, so without it.
- `/analyze` privacy: `background.js` sends `shareableUrl(snapshot.url)` (`domain.js`: origin + path); the full URL stays on the device for layer 2. `snapshot.text` is `ShooSnapshot.pageText`: `innerText` minus `[contenteditable]` areas.
- Every network call goes through `background.js` (content scripts run under the page's origin).
- `Resources/psl.js` is GENERATED — refresh with `scripts/update-psl.sh`, never edit by hand.
- Tests (Node, no device needed): `node --test ios/ShooExtension/Tests/*.test.mjs`. `Tests/` and `scripts/` are excluded from the bundle in `project.yml`.
- The device token stays in `background.js`: no `runtime.onMessage` reply carries the token or the base URLs (`profile` gives blocked.html only onboarded/mode/guardianName).
