Apa yang sama, apa yang beda

Sama

  • Hampir semua jawaban yang selesai: reasonable:false (DeepSeek 100%; GLM satu pengecualian, lihat “Beda”).
  • page_type sama: courier (DHL) dan other (bansos). Tidak ada yang menebak government/prize karena teks halaman tidak dikirim ke LLM.
  • evidence selalu disalin dari judul halaman.
  • Skor akhir identik per jenis hasil: DHL 15 → 45, bansos 40 → 70.
  • Reasoning memakan 82–100% waktu; max_tokens: 200 diabaikan proxy (completion ±1.200–1.800 token).
  • Layer 1–3 identik karena tidak bergantung model.

Beda

  • Timeout: DHL DeepSeek 6/10 vs GLM 3/10 (dua sesi sama). Bansos DeepSeek 2/10 vs GLM 4/10. Arahnya terbalik antar-link.
  • Confidence: DeepSeek lebih tinggi di DHL (0,85–0,95) dibanding GLM (0,65–0,85).
  • Kepatuhan format: DeepSeek 0 pelanggaran. GLM 1 reasonable:true (DHL, conf 0,45) dan 1 bad_schema (asks berisi "email", di luar enum).
  • Ekor latensi: GLM 1 panggilan 90 s abort (bansos) dan stream 22 s (DHL). DeepSeek stream 45,7 s (testing 15, reasoning off) dan 10–11 s.
  • asks berubah-ubah antar-run di kedua model; tidak memengaruhi skor.
  • DeepSeek reasoning off tidak mempercepat: parameter terkirim tapi proxy mengabaikannya (6 timeout, sama dengan bawaan).

Kesimpulan

Tidak ada pemenang jelas dari data ini

  1. Akurasi arah sama. Ketika menjawab, kedua model menandai halaman scam sebagai tidak wajar dengan skor akhir sama. Selisihnya ada di jarang-tapi-nyata: GLM pernah meloloskan DHL palsu (reasonable:true) dan pernah melanggar format; DeepSeek tidak pada sampel valid.
  2. Kecepatan sebanding, bukan unggul. Median run selesai 3–4 s di kedua model; keduanya sering menembus batas 6 s karena reasoning. GLM lebih sedikit timeout di DHL (30% vs 60%), DeepSeek lebih sedikit di bansos (20% vs 40%). Jam, beban penyedia, dan n = 10 tidak cukup untuk menyebut satu lebih cepat.
  3. Dampak nyata ada di link DHL. Skor layer 3 hanya 15, jadi tiap timeout = halaman scam lolos: DeepSeek 6/10 (60%), GLM 4/10 (40%: 3 timeout + 1 reasonable atau bad_schema), di kedua sesi GLM. Di bansos, layer 3 menutup celah itu sendiri (10/10 run skor ≥ 30).
  4. DeepSeek lebih yakin dan lebih rapi (confidence tinggi, schema bersih). GLM sedikit lebih sering selesai di DHL tapi kurang konsisten pada format dan ambang “wajar”.
  5. Mematikan reasoning lewat parameter tidak bekerja di proxy ini; bukan solusi kecepatan.

Belum terbukti

  • Akurasi pada halaman sah (satu-satunya halaman sah, klikBCA, tidak memanggil LLM): false positive tiap model belum terukur.
  • Kecepatan jam lain, link lain, dan dari Cloudflare Worker. Layer 1 dan RDAP tidak ikut.

Saran berikutnya (belum dijalankan)

  • Jalankan bandingkan model glm-5.3-flash,deepseek-v4-flash pada satu sesi/jam yang sama, di ≥ 3 link scam + ≥ 3 link sah.
  • Tambah DHL ke brands.json supaya layer 3 tidak bergantung pada LLM untuk kasus ini.
  • Pisahkan status provider_error dari bad_schema di ai/src; pertimbangkan batas layer 4 lebih longgar atau model non-reasoning.
