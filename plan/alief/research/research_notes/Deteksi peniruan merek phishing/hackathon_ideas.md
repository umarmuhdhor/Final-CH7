# Hackathon projects on phishing, scam, fraud and impersonation detection (Devpost, lablab.ai and others, 2022–2026): what won, how it detected scams, and what Shoo can adopt

Scope note (researched 2026-10-26). This file covers hackathon projects only. It does not repeat the academic material in `brand_impersonation_methods.md` (Phishpedia, PhishIntention, KnowPhish, PhishLLM, the brand + CRP + domain rule, favicon hashing, resource origin) or in `systematic_reviews.md` (PHILTER SoK, evaluation pitfalls, Safe Browsing design, CRP gate). Where a hackathon idea is just a lighter version of one of those methods, this file says so and points there.

How the evidence was collected:
- Devpost has a public JSON search endpoint (`https://devpost.com/software/search?query=<term>&page=<n>`, 6 projects per page). Each project card has a `winner` true/false flag. Totals reported by the endpoint: "phishing" 2,082 projects, "scam" 2,919, "fraud" 5,538, "scam call" 889, "impersonation" 648 — [Devpost search](https://devpost.com/software/search?query=phishing).
- I read 202 result pages (893 unique project cards) for 12 search terms. Then Devpost's Cloudflare bot challenge ("Just a moment...") started blocking most requests. I did not try to get around it, so **coverage is partial**. Projects that won but were not on the pages I read are missing from this file.
- For about 30 candidate projects I then fetched the public project page one at a time and read the "Submitted to / Winner" block and the story. A placement is marked **verified** only when that block shows it. Devpost search results through WebSearch added a few more candidates.
- lablab.ai pages were read through WebFetch and curl. Its app search ignores the query string, so lablab coverage relies on web search and is thin.
- I did not log in or submit anything.

Placement labels used below:
- **verified**: the "Winner …" text is on the project's Devpost page.
- **participation**: the page says "Winner", but the prize is a participation or shortlist badge (ForgeHacks "Winner All Participants / All Teams", "Participation Prizes", "Round 1 Shortlisted Teams"). These are not merit wins.
- **unverified**: the `winner` flag is true in Devpost search data, or a third party says the project won, but the project page shows no prize text.

## Q1. Which hackathon projects won or placed for phishing/scam detection, and how exactly did they detect scams?

### Takeaway
On Devpost, every phishing/scam project I could verify as a 2023–2026 merit winner uses one of four cheap patterns: (a) text classification of messages, or rules plus an LLM; (b) live call transcription plus an LLM tactic check; (c) URL reputation APIs; or (d) URL heuristics plus RDAP domain age. None of the verified winners runs a screenshot plus vision-LLM brand check. The Devpost projects that do run one (Hybrid Anti-Phishing, Guardian for Alexa+) did not place. The strongest winners for Shoo's purposes are about *intervention design* (family alerts, deterministic hold rules, evidence-quoting warnings), not about better page detection. I found no verified phishing/scam winner on lablab.ai, ETHGlobal, or the Gemini API Developer Competition.

### Cited Findings

**Live phone-call scam interception (largest group of recent winners)**
- **Canary AI**, Rowdy Hacks XII, "Winner Swivel Challenge 1st Place" (verified), October 2026. It bridges unknown calls through Twilio Conference and Media Streams, then transcribes them with Deepgram. A "dual-path" engine checks every *finalized* sentence against instant triggers (gift cards, verification codes, remote access) and adds up scores for pressure tactics (authority, urgency, secrecy). Google Gemini runs in parallel for intent. On detection it plays an ElevenLabs audio warning *into the call* and texts a trusted contact "the exact trigger phrase". Test claim: "64 synthetic scam scripts across 8 categories … while keeping the system completely silent on legitimate calls" (no numbers given for the legitimate set). Stack: Node.js, TypeScript, Fastify, LibSQL, React. — [Devpost: Canary AI](https://devpost.com/software/canary-ai-c1y6d8)
- **Scout: live scam call protection**, built for Sound Credit Union members (HuskyHack challenge data), October 2026. Placement is **unverified**: search data flags it `winner: true`, but the page shows no prize block. Calls are forwarded through Scout. About 75 English/Spanish pattern rules fire instantly, and Claude re-checks the conversation after every caller phrase. A "neural vocoder artifact screener" flags AI-cloned voices. The decision is plain code, not AI: hold the caller if c ≥ 0.85, or if the voice is AI **and** c ≥ 0.60. "An AI voice alone never holds a call". Claimed results: 44/44 scam scenarios flagged and 0/44 normal look-alikes; 79/80 on public scam-call data and 0/110 normal; about 3 s from the scammer's request to the hold; "Across 214 normal-call test runs, Scout never once rated a normal call 'likely scam'". Staff can "freeze the member's outgoing transfers for 24 hours". It saves no audio and deletes the transcript of unflagged calls. — [Devpost: Scout (avtc5s)](https://devpost.com/software/scout-live-scam-call-protection-avtc5s)
- The Scout team's reading of the challenge data: "money moves a median 12 minutes after the scam starts, but the first intervention comes at 16 minutes". "Generic pop-up warnings were shown in 12 scam journeys and prevented none of them". Victims told the credit union "yes, I intended this" 44 times because the scammer was coaching them. "Scam payments went to a brand-new payee 92.3% of the time, versus 4.0% for routine payments" (7,471 events, 118 members). These are the team's numbers from a hackathon dataset, not peer-reviewed. — [Devpost: Scout](https://devpost.com/software/scout-live-scam-call-protection)
- **Scam-Mah**, NewHacks 2024, "Winner 3rd Place Overall" (verified). It flags callers with "atypically-high call rates and atypically-low average call durations" (StandardScaler + IsolationForest). Suspected scam calls can be handed to Gemini + ElevenLabs TTS, which replies humorously "to waste the scammer's time". The demo is a website only. — [Devpost: Scam-Mah](https://devpost.com/software/scam-mah)
- **ScamStop**, MAIS Hacks 2025, "Winner Best Hack for Laugh" (verified, a joke category). Live speech-to-text (RealtimeSTT) feeds a *local* LLM (Ollama, olmo2:13b) that looks for urgency, threats and requests for sensitive information. — [Devpost: ScamStop](https://devpost.com/software/stopscam)
- **ElderGuard AI**, Production Agents Hackathon, "Winner Top Overall Winners" (verified), November 2025. It is a deepfake-voice flag plus family notification plus "safe verification questions". The team states that the Hugging Face voice model inference was "mocked … for speed", with pre-recorded samples and Postman mock APIs. So this is a UX prototype, not a working detector. — [Devpost: ElderGuard AI](https://devpost.com/software/elderguard-ai)

**SMS / message scanners**
- **PhishLens (Android)**, STEMist Hacks IV, "Winner Best Security or Privacy Hack 1st" (verified), August 2026. An Android AccessibilityService reads the browser address bar and shows a floating warning overlay. An SMS receiver scans incoming texts for urgency keywords and links. A live **RDAP lookup flags domains under 30 days old (+30 risk points)**. Groq Llama-3.1-8B writes a non-technical explanation. ML Kit OCR reads screenshots and CameraX decodes QR codes. Scan history stays in local SQLite. — [Devpost: PhishLens](https://devpost.com/software/phishlens-uzveqd)
- **Vigil Safety**, submitted to several events. The page shows "Winner 1st Place any track" and "Winner 1st Place Any other Track besides ML …(CASH PRIZE)" (verified wording, but the page does not make clear which event each prize belongs to). It classifies incoming SMS as SAFE/SCAM/HARASSMENT with an on-device language model ("no AI API, no API keys, and no internet connection at all"). Before classifying, it "undoes spacing/character tricks". Keyword rules run in parallel, and an alert fires unless both checks say safe. — [Devpost: Vigil Safety](https://devpost.com/software/vigil-safety-app)
- **Reveal** (participation: "Round 1 Shortlisted Teams", Zero Origin). On-device DistilBERT, int8-quantized and run with ONNX Runtime, with a custom Kotlin WordPiece tokenizer. The app "does not even ask for Android's INTERNET permission". Its warning chip appears only while the user is inside the messaging app. — [Devpost: Reveal](https://devpost.com/software/reveal-yxnue4)
- **DataFirst**, TLN Hackathon 2026 / Financial Cybersecurity Challenge 2026, "Winner First Place" (verified). A native iOS app (Swift, SwiftUI) that uses on-device Core ML, SoundAnalysis, Speech and Vision to check calls, texts and screenshots for personal-data requests and scam speech, with local notifications. It reports no accuracy. — [Devpost: DataFirst](https://devpost.com/software/datafirst-q8dyb6)
- **Scan My SMS**, Pangea Securathon, "Winner Third Prize" (verified), June 2023, Israel. Users submit SMS links. A worker opens each link in **Chromium via Playwright and follows "all pages and redirects"**, then adds Pangea.Cloud URL reputation, IP geolocation and certificate checks. A **Telegram group of volunteers** labels URLs that automation could not classify and can override verdicts. — [Devpost: Scan My SMS](https://devpost.com/software/scan-my-sms)
- **AntiFish**, HenHacks 2026, "Winner Security & Safety – Sponsored by LabWare" (verified). A TF-IDF + logistic-regression probability is blended **60/40** with a rule overlay (urgency, gift cards, credential prompts, suspicious links) into LOW/SUSPICIOUS/HIGH. It adds a "Downdetector-like" feed of trending scam campaigns. — [Devpost: AntiFish](https://devpost.com/software/antifish-dackeq)
- **Tellsign** (participation: ForgeHacks "Winner All Participants / All Teams"). A rule engine and an LLM (Groq gpt-oss-120b) run together. It quotes "the exact red-flag phrases", works in 13 languages with per-language prompts ("Scams do not translate word for word"), and gives country-specific reporting contacts. The team reports that the hybrid "beat either approach on its own" but gives no numbers. — [Devpost: Tellsign](https://devpost.com/software/fill-the-blanks-tellsign-ai-scam-detection-protection)

**URL / web-page checkers and browser extensions**
- **SafeLinkScanner**, World's Largest Hackathon presented by Bolt, "Winner Bonus Prizes | One-Shot Competition" (verified), June 2025. It gives a 1–10 score from Google Safe Browsing, VirusTotal and PhishTank plus SSL validity, and was generated from a single Bolt.new prompt. — [Devpost: SafeLinkScanner](https://devpost.com/software/safelinkscanner-url-security-analysis-tool)
- **PhishFinder**, WebHack, "Winner 2nd Place – Division 2" and "Winner Outstanding Code" (verified), February 2023. A Chrome extension injects into Gmail, extracts the selected email's sender and body, sends them to GPT-3, and shows a status label next to the subject. — [Devpost: PhishFinder](https://devpost.com/software/phishfinder)
- **PhishShield AI**, DeveloperWeek 2025 Hackathon, "Winner DeveloperWeek 2025 Overall Winner" (verified). A Streamlit app with a scikit-learn email/URL classifier. "Achieved high accuracy" is stated with no number, and the browser extension is only listed under "what's next". — [Devpost: PhishShield AI](https://devpost.com/software/phishshield-ai)
- [older, 2020] **PhishingNet**, HackMHS, "Winner Second Place" (verified). A Chrome extension using an ML.NET NLP model on page text plus an HTTPS-certificate check. — [Devpost: PhishingNet](https://devpost.com/software/phishingnet)

**Notable non-winners whose methods are closest to Shoo (placement not shown = no prize listed)**
- **Hybrid Anti-Phishing Browser Extension**, Google Chrome Built-in AI Challenge, December 2024, no prize shown. It checks a blacklist first, then a whitelist (to skip LLM cost), then takes a screenshot and sends it to multimodal Gemini on a backend "to verify if the page URL matches what is visible in the screenshot". It uses Chrome's built-in language-detector API, but "there was no multimodal prompt API available" on-device. This is the hackathon version of the identity-based (brand vs domain) family already covered in `brand_impersonation_methods.md`. — [Devpost: Hybrid Anti-Phishing](https://devpost.com/software/hybrid-anti-phishing-browser-extension)
- **Guardian: scam protection for Alexa+**, Build, Ship, Shape: Amazon Developer Hackathon, October 2026, no prize shown. It is an MCP server that opens a link in a **sandboxed headless Chromium (Playwright)**, with an SSRF guard that rejects private addresses and checks every redirect hop. It takes a screenshot and gives one of three verdicts: "Don't open this link", "Be careful", "No red flags found". It **never says "Safe"**. It is "Rule-based on purpose. There is no LLM inside the server, so a malicious page can't prompt-inject the thing that judges it". Checks: look-alike domains, "brand pages hosted off the brand's real domain", RDAP, requests for PINs/codes/card details, and "hidden instructions aimed at an AI". Caller check: "Guardian messages the real Amaan on Telegram with Yes/No buttons". About 165 automated tests. — [Devpost: Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa)
- **PhishLens (MV3 extension)**, TLN Hackathon 2026, no prize shown. All checks run locally, with no blocklists ("Privacy constraint = no blocklists"). It folds confusable characters, then applies Levenshtein distance (paypa1, xn--pple-43d.com), flags `brand.com.secure.evil.top`-style subdomain stuffing, password forms posting cross-site or over HTTP, fields for CVV/SSN/OTP/seed phrase, hidden iframes, and urgency text. The output is a 0–100 score with a reason per flag, shown in a Shadow-DOM in-page banner. About 400 lines of dependency-free JS shared by the content script, popup and demo. — [Devpost: PhishLens (slt1qi)](https://devpost.com/software/phishlens-slt1qi)
- **PhishGuard AI**, Global Innovation Build Challenge V2, no prize shown. It runs a deterministic URL and brand-mismatch engine plus RDAP plus optional VirusTotal, and a *local* LLM (Ollama Qwen 2.5) for tone. It stores only "a SHA-256 input hash alongside structured detection evidence" (zero raw content persistence), has an SSRF guard, and treats message text as untrusted in prompts. — [Devpost: PhishGuard AI](https://devpost.com/software/phishguard-ai-901a7k)

**Fraud / payment and family-money agents**
- **TrustPay** (participation: "Winner Participation Prizes", NextStep Hacks 2026; Visa Verify track). It scores checkout behaviour (typing cadence, paste-vs-type, form-fill speed) from 0 to 100, with an explanation for every point. Its Chrome extension shows an "Is this payment page safe?" card, and one demo badge reads "Form also asks for ATM PIN". — [Devpost: TrustPay](https://devpost.com/software/trustpay-87qfiy)
- **Kinwise**, Agents for Humans Hackathon (Strands Agents SDK), no prize shown. "Quiet mode, no model: 10 deterministic detectors". A correlator scores signals in a 3-hour window and only then wakes the agent. The agent holds the payment and asks the adult child one question: "Block & call Mom, or release". A `BeforeToolCallEvent` hook blocks `release_hold` while the scammer is on the line. "Amounts and transaction links are computed in code, never taken from the model". — [Devpost: Kinwise](https://devpost.com/software/kinwise-a-quiet-guardian-for-mom-s-money)

**Education / games**
- **Bot or Not?**, MIT BWSI Cyber Operations Cohort Hackathon 2026, "Winner Bronze Project (3rd Place)" (verified). A "GeoGuessr of AI detection" game for older adults covering AI images, scam emails and AI voices, with lives, combos and time-decaying points. — [Devpost: Bot or Not?](https://devpost.com/software/bot-or-not-3ig4un)
- **Scampot**, CSPSC Hacks, "Winner 1st Place" (verified), September 2024. A Figma-only design for an elderly link scanner plus a quiz. The author says the app is not built. — [Devpost: Scampot](https://devpost.com/software/scampot)

**Indonesia-relevant**
- **GambitHunter**, OpenAI Codex Hackathon (Singapore), 2nd place, late February 2026, by three Indonesian engineers. It is an AI agent that browses online-gambling (judol) sites and collects the **bank account numbers and phone numbers used for deposits**, instead of chasing domains. The article gives no counts or accuracy. Stack: GPT-5.2 and Codex. Source is a news article, not a project page. — [detik inet](https://inet.detik.com/cyberlife/d-8401899/kisah-3-engineer-ri-bikin-ai-pemburu-judol-juara-hackathon-openai)
- Open-source Indonesian tools found in the same search, **not** hackathon winners: ScamLens ID (paste WhatsApp/SMS text or a URL and get a 0–100 score with reasons in Indonesian) — [GitHub: scamlens-id](https://github.com/patrickivanuellf/scamlens-id); Waspada (check messages, URLs, phone numbers and bank/e-wallet accounts) — [GitHub: waspada](https://github.com/hfzzd/waspada).

Entries seen without placement: PhishGuard AI (email analysis in plain language; page shows no winner text) — [lablab: phishguardai](https://lablab.ai/ai-hackathons/nativebuilder-build-without-limits/muniza-shaikh/phishguardai); RedLine, a voice-phishing *drill coach*, AssemblyAI Voice Agent Hackathon, 30 Sep 2026. ### Inferences
- Judges reward working end-to-end loops (call → transcription → LLM → alert to family) more than detection quality. Few winners report a false-positive rate, and most rely on LLM-plus-rules on text.
- Visual brand impersonation, which is Shoo's main research topic, is almost absent among verified hackathon winners. This is a sign that it is hard to do well in a weekend, not that it doesn't matter. Academic sources remain the reference for that layer.
- Several winners (Scout, Kinwise, Canary) converge on one architecture: deterministic rules decide, the LLM only advises or explains. This matches Shoo's layered detector.

### Gaps
- Devpost coverage is partial (202 of several thousand result pages) because of the Cloudflare challenge. More winners likely exist, especially before 2024.
- Scout's prize name could not be verified on its page.
- lablab.ai winner lists per event were not searchable by keyword, and I found no verified lablab winner in scope. The "FRAUDAPT" (AI Genesis) entry came only from a search summary and was not opened.
- No ETHGlobal showcase project on wallet-drainer or phishing detection with a finalist badge was found. HackerEarth, Kaggle and Microsoft Imagine Cup were not reached in the tool budget.
- No QR-phishing ("quishing") hackathon winner was found.

## Q2. Which UX and product ideas stood out (warnings, explanations, guardian/family alerts, education, "ask someone before paying")?

### Takeaway
The most transferable ideas are about who gets warned and how the warning is worded: warn the family as well as (or instead of) the victim, quote the specific evidence, never say "safe", use three plain verdict levels, let a trusted person confirm "is it really them?", and put a human decision before money moves. Several teams say they learned that generic pop-ups fail and that false alarms make users disable the tool.

### Cited Findings
- Warn the family, not the victim: "Every app I looked at warns the person who received the message. That is the one person the scam has already fooled. But a warning from their own son or daughter, they believe immediately". The protected owner "is never asked to decide anything". The family receives the reasons in Azerbaijani, Russian or English. The team claims "90.3% of smishing caught on the held-out half, 1.9% false alarms" on 4,538 real Azerbaijani messages, reproducible from the repo (EurekaDev 2026, no prize shown). Reason codes include `BRAND_MISMATCH`, `PRIZE_CLAIM`, `CALLBACK`. A scam with no link ("prize + number to ring") was what "Four out of five scams this detector used to miss looked like". — [Devpost: Qayğısız](https://devpost.com/software/qaygisiz)
- Evidence over labels: Canary sends "the exact triggering quote (e.g., 'asked for gift card numbers') … rather than an unexplained risk score". The team learned "False Alarms Destroy Trust" and "Transparency Over Labels: Presenting evidence and letting family members make the final decision". — [Devpost: Canary AI](https://devpost.com/software/canary-ai-c1y6d8)
- Never say "Safe". Guardian's verdicts are "Don't open this link" / "Be careful" / "No red flags found", "because no checker can promise that". Reasons are short sentences meant to be read aloud. — [Devpost: Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa)
- Out-of-band identity check through the family: "Is it really Amaan calling?" sends the real Amaan a Telegram message with Yes/No buttons, "so Mum hears the answer from her family, not from the caller". — [Devpost: Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa). Handshake pairs trusted devices through a short-lived, single-use QR invitation and aims to "verify the person, not the voice" (ForgeHacks participation badge) — [Devpost: Handshake](https://devpost.com/software/handshake-m7hjb8).
- Human gate before money moves: Kinwise asks the adult child "exactly one question: Block & call Mom, or release". Scout gives the member three choices during a call: continue, end, or connect to the credit union. It lets staff freeze outgoing transfers for 24 hours. — [Devpost: Kinwise](https://devpost.com/software/kinwise-a-quiet-guardian-for-mom-s-money); [Devpost: Scout](https://devpost.com/software/scout-live-scam-call-protection-avtc5s)
- Timing beats wording: in the HuskyHack data "Generic pop-up warnings were shown in 12 scam journeys and prevented none of them", and coached victims confirmed "yes, I intended this" 44 times. — [Devpost: Scout](https://devpost.com/software/scout-live-scam-call-protection)
- Context-aware alert placement: Reveal's warning chip appears only while the user is in the messaging app, "avoiding annoying pop-ups during games or videos". — [Devpost: Reveal](https://devpost.com/software/reveal-yxnue4)
- The warning as a micro-lesson: PhishLens's in-page banner lists "exactly which signals fired — so the warning itself is a micro-lesson". — [Devpost: PhishLens (slt1qi)](https://devpost.com/software/phishlens-slt1qi)
- After-the-fact recovery: Guardian has "I gave someone my code" playbooks, "one calm step at a time, starting with calling the bank". Handshake has a "first 60 minutes after money has been sent" checklist. Tellsign gives verified national reporting contacts ("Real help, not 'contact your local authorities'"). — [Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa); [Handshake](https://devpost.com/software/handshake-m7hjb8); [Tellsign](https://devpost.com/software/fill-the-blanks-tellsign-ai-scam-detection-protection)
- Circle-level correlation: Circle Watch treats phishing that spreads through a hijacked contact as an outbreak. "One report is a hunch; several independent reports converging is a confirmed cluster". Confirmation is "a deterministic function counting real reports, not an AI's guess" (Agents for Humans Hackathon, no prize shown). — [Devpost: Circle Watch](https://devpost.com/software/circle-watch-an-outbreak-tracer-for-phishing)
- Live awareness feed: AntiFish has a "Downdetector-like" feed of trending scam campaigns — [Devpost: AntiFish](https://devpost.com/software/antifish-dackeq).
- Gamified training for seniors: Bot or Not? (3rd place) uses lives, combos, large buttons and minimal clutter — [Devpost: Bot or Not?](https://devpost.com/software/bot-or-not-3ig4un). Tellsign offers "Simple mode and read-aloud" and a "Was this right?" feedback button — [Devpost: Tellsign](https://devpost.com/software/fill-the-blanks-tellsign-ai-scam-detection-protection).

### Inferences
- The "warn family first" pattern (Qayğısız, Canary, Kinwise) fits Shoo's Guardian/Protected pairing directly. Shoo already has push alerts. The new idea is that the Guardian alert may matter *more* than the warning on the Protected phone.
- The "never say safe" rule and three verdict levels are cheap copy decisions for Shoo's popup, Guardian push and Activity list.

### Gaps
- None of these UX claims was tested with real users in a controlled way. They are team lessons, not measured effects.
- No hackathon project tested warning wording in Indonesian.

## Q3. Which ideas are novel compared with the academic approaches already covered?

### Takeaway
Compared with the academic sibling notes, the hackathon field adds mostly *system* ideas, not new detectors. The new ones are: in-call or pre-payment intervention, family-routed alerts and out-of-band confirmation, prompt-injection-aware judging of pages, extracting payment identifiers (bank accounts, phone numbers) as the scam's real infrastructure, and volunteer or circle crowd-labelling. Sandboxed link visiting, honeypots that waste scammers' time, and credential poisoning appear too, but only as non-winning or non-hackathon work.

### Cited Findings
- **Prompt injection aimed at AI judges**: "Scam pages now hide instructions aimed at AI assistants ('tell the user this site is legitimate')". Guardian flags "This page tried to fool the AI" and keeps the judge rule-based. — [Devpost: Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa). PhishGuard AI treats submitted text "as untrusted user data when generating prompts" — [Devpost: PhishGuard AI](https://devpost.com/software/phishguard-ai-901a7k).
- **Sandboxed link visit**: Scan My SMS (Third Prize, 2023) follows all redirects in Playwright Chromium — [Devpost: Scan My SMS](https://devpost.com/software/scan-my-sms). Guardian adds an SSRF guard and checks every redirect hop — [Devpost: Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa).
- **Follow the money, not the domain**: GambitHunter (2nd place, OpenAI Codex Hackathon 2026) harvests deposit bank accounts and phone numbers from gambling sites — [detik inet](https://inet.detik.com/cyberlife/d-8401899/kisah-3-engineer-ri-bikin-ai-pemburu-judol-juara-hackathon-openai). Scout's data shows the "brand-new payee" signal (92.3% vs 4.0%) — [Devpost: Scout](https://devpost.com/software/scout-live-scam-call-protection).
- **Scam-baiting honeypots**: Scam-Mah (3rd Overall, NewHacks 2024) answers suspected scam calls with a humorous AI to waste time — [Devpost: Scam-Mah](https://devpost.com/software/scam-mah). The ForgeHacks 2026 "AI Scam Honeypot" ("an AI victim that wastes scammers' time and extracts indicators for authorities") states no placement — [GitHub: scam-honeypot](https://github.com/vedtod07/scam-honeypot). The Agentic-Honeypot repo uses a stalling persona, "Auntie Janice", to extract bank accounts, UPI IDs and phishing links, with no placement stated — [GitHub: Agentic-Honeypot](https://github.com/Ndhakeph/Agentic-Honeypot).
- **Credential poisoning**: not found as a hackathon winner. Open-source tools exist that "flood phishers' databases with fake but credible information" — [GitHub: drowned_phish](https://github.com/ndoxx/drowned_phish); [GitHub: phisherman](https://github.com/maxijonson/phisherman). A patent describes entering invalid credentials into a phishing form and watching for their use against the real service (credential canary) — [USPTO 12531901](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/12531901).
- **Crowd plus human-in-the-loop labelling**: Scan My SMS's volunteer Telegram group overrides automated verdicts — [Devpost: Scan My SMS](https://devpost.com/software/scan-my-sms). Circle Watch confirms clusters by counting independent reports — [Devpost: Circle Watch](https://devpost.com/software/circle-watch-an-outbreak-tracer-for-phishing).
- **Deterministic decision, LLM advisory**: Scout's hold formula (c ≥ 0.85, or AI voice and c ≥ 0.60) — [Devpost: Scout](https://devpost.com/software/scout-live-scam-call-protection-avtc5s). Kinwise "Amounts … computed in code, never taken from the model" — [Devpost: Kinwise](https://devpost.com/software/kinwise-a-quiet-guardian-for-mom-s-money).
- **Verify identity instead of detecting deepfakes**: Handshake: "What if we stopped trying to detect fake voices and instead made it easier to verify real people?" — [Devpost: Handshake](https://devpost.com/software/handshake-m7hjb8).
- **QR codes**: only PhishLens (Android winner) decodes QR codes into the same URL pipeline, and that is a feature, not a new method — [Devpost: PhishLens](https://devpost.com/software/phishlens-uzveqd).

### Inferences
- Prompt injection is the novel idea that matters most for Shoo. Shoo has an LLM layer on the server, and any page-derived text that reaches it can contain instructions to the model. The academic notes in this folder do not cover this attack on the detector itself.
- Honeypots and credential poisoning are out of scope for a consumer iPhone app. They need Shoo to interact with attacker infrastructure, which brings legal and safety risk (the search summary on poisoning tools flagged computer-misuse concerns, but that was not a primary source).

### Gaps
- No hackathon project measured how often real phishing pages contain AI-targeted prompt injections. Guardian demonstrates it only on its own fictional page.
- No hackathon payment-confirmation interstitial for web checkout (as opposed to bank-side holds) with any evaluation was found.

## Q5. Which ideas fit Shoo (iPhone Safari extension, Guardian/Protected app with push, Cloudflare Workers + LLM, Indonesian users, privacy-first)?

### Takeaway
High fit and low cost: (1) a Guardian alert with reason codes, framed as "your family member was stopped from X", not just a warning on the Protected phone; (2) three-level verdict copy that never says "aman"; (3) a payment/OTP/PIN-field interstitial on non-brand domains; (4) RDAP domain age in the Worker using only the hostname; (5) keep the LLM advisory and resistant to prompt injection, with a deterministic final rule; (6) a "Tanya keluarga dulu" (ask family first) action that pings the Guardian with Yes/No. Medium fit: correlating blocks across one family's devices, and extracting bank account / e-wallet numbers shown on a page. Low fit: screenshot vision checks (conflicts with the no-screenshot rule), honeypots, credential poisoning, call interception (iOS gives no third-party call audio).

### Cited Findings
- Each fit judgment below builds on a cited project. The fit reasoning is my inference, listed in Inferences.
  - Family-routed alert with reason codes: [Qayğısız](https://devpost.com/software/qaygisiz), [Canary AI](https://devpost.com/software/canary-ai-c1y6d8).
  - Three verdicts, never "Safe": [Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa).
  - Fields for CVV/SSN/OTP/seed phrase and password forms posting cross-site: [PhishLens (slt1qi)](https://devpost.com/software/phishlens-slt1qi). The "Form also asks for ATM PIN" badge: [TrustPay](https://devpost.com/software/trustpay-87qfiy).
  - RDAP age under 30 days scored as +30: [PhishLens Android](https://devpost.com/software/phishlens-uzveqd). RDAP in Guardian, PhishGuard AI and Circle Watch: [Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa), [PhishGuard AI](https://devpost.com/software/phishguard-ai-901a7k), [Circle Watch](https://devpost.com/software/circle-watch-an-outbreak-tracer-for-phishing).
  - Rule-based judge to avoid prompt injection: [Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa). Deterministic hold rule: [Scout](https://devpost.com/software/scout-live-scam-call-protection-avtc5s).
  - Ask the real person through a second channel: [Guardian](https://devpost.com/software/prompt-injection-firewall-for-alexa); one-question decision: [Kinwise](https://devpost.com/software/kinwise-a-quiet-guardian-for-mom-s-money).
  - Hash-only storage of inputs: [PhishGuard AI](https://devpost.com/software/phishguard-ai-901a7k). On-device only, no network permission: [Reveal](https://devpost.com/software/reveal-yxnue4), [Vigil Safety](https://devpost.com/software/vigil-safety-app). Native iOS on-device frameworks (Core ML, Vision, Speech): [DataFirst](https://devpost.com/software/datafirst-q8dyb6).
  - Report correlation within a circle: [Circle Watch](https://devpost.com/software/circle-watch-an-outbreak-tracer-for-phishing).
  - Payment identifiers as the scam's infrastructure: [GambitHunter, detik](https://inet.detik.com/cyberlife/d-8401899/kisah-3-engineer-ri-bikin-ai-pemburu-judol-juara-hackathon-openai); Indonesian bank/e-wallet/phone check tool: [Waspada](https://github.com/hfzzd/waspada).
  - Screenshot to a server vision LLM: [Hybrid Anti-Phishing](https://devpost.com/software/hybrid-anti-phishing-browser-extension).

### Inferences
Fit table. Constraints used: the content script reads the DOM; the background sees webRequest on iOS 18.4+; the app has Guardian/Protected pairing with push; the server is a Cloudflare Worker with an LLM layer; minimal data leaves the phone and no screenshots or page text are stored; users are Indonesian.

| Idea (source) | Fit | How it maps to Shoo | Privacy note |
|---|---|---|---|
| Family-first alert with reason codes (Qayğısız, Canary) | High | Guardian push: "Situs tiruan BCA diblokir di HP Ibu" (fake BCA site blocked on Mum's phone) plus 1–3 reason codes (BRAND_MISMATCH, NEW_DOMAIN, ASKS_OTP) | Send the reason codes and hostname, not the page text or Canary-style quotes |
| Never say "aman" (safe); three verdicts (Guardian) | High | Popup/Activity copy: "Jangan buka" (don't open) / "Hati-hati" (be careful) / "Tidak ada tanda bahaya" (no warning signs) | None |
| OTP/PIN/CVV field on a non-brand domain triggers an interstitial (PhishLens slt1qi, TrustPay) | High | The content script already reads the DOM. A field named or labelled OTP/PIN/CVV plus a brand mismatch is a strong local signal. It matches the CRP gate in `systematic_reviews.md` Q4 and extends it to payment fields | Fully on-device |
| RDAP domain age (PhishLens Android, Guardian, PhishGuard) | High | Worker looks up RDAP for the registrable domain only and caches the result | Hostname only; check whether the Worker already does WHOIS/RDAP (see `url_domain_tls.md`) |
| Deterministic final rule, LLM advisory only, prompt-injection-aware (Scout, Kinwise, Guardian) | High | The LLM layer returns structured fields. Code decides block/warn. Treat any page-derived string sent to the LLM as untrusted, and add a rule that flags hidden "to the AI" text | Reduces what is sent to the LLM |
| "Tanya keluarga dulu" Yes/No to the Guardian (Guardian/Alexa, Kinwise) | High–medium | From the warning page, the Protected user taps once. The Guardian gets a push with "Izinkan / Tetap blokir" (allow / keep blocked). This needs a new push action and contract change, so Lead approval is needed (`contracts/`) | Only the hostname and reason codes leave the device |
| Family-circle correlation (Circle Watch) | Medium | If 2+ devices in one pairing hit the same new domain, raise its severity server-side within the 14-day retention | Hostname-level only; it fits the existing Activity data |
| Extract bank account / e-wallet / phone numbers from page text (GambitHunter, Waspada) | Medium | A content-script regex for Indonesian account and e-wallet formats on pages that ask for transfers. Check against a reported-account list | Must hash or compare on-device. Which Indonesian lists exist and how they license is unknown (Gaps) |
| Hash-only storage of inputs (PhishGuard AI) | Medium | If the Worker keeps verdict caches, key them by URL hash | Already aligned with the privacy rules |
| Gamified "Latihan" (practice) quiz for Protected users (Bot or Not?, Scampot) | Low–medium | Optional app screen; not core | None |
| Screenshot to vision LLM (Hybrid Anti-Phishing, Guardian sandbox) | Low | Conflicts with "no screenshots stored/sent". A Worker-side sandbox fetch of the URL (no user data) is possible, but costly on Workers and liable to cloaking | Server-side fetch sends only the URL |
| Live call interception (Canary, Scout) | Not feasible | iOS does not give third-party apps call audio. Out of Shoo's scope | n/a |
| Honeypots, credential poisoning (Scam-Mah, drowned_phish) | Not fit | Legal risk; Shoo would interact with attacker infrastructure | n/a |

### Gaps
- Whether Indonesia has a public, licensable reported-account list (for the bank account / e-wallet idea) was not researched here and needs checking.
- No hackathon project targeted Safari on iOS. All browser projects were Chrome MV3 or Android AccessibilityService. iOS-specific constraints (webRequest on iOS 18.4+, extension memory limits) are not tested by any of them.
- The "Tanya keluarga dulu" flow and the reason-code push payload would need a `contracts/` change. Per repo rules that is a GitHub issue to the Lead, not something to decide in this note.
