Semua layar Fase A (ON-01..05, PR-04/05, GD-01/02/03/05, DT-01..06, PF-01) berjalan di kedua mode dan kedua bahasa tanpa crash, tanpa teks Inggris yang bocor di mode ID, dan tanpa data keluarga lain yang terlihat. Alur inti sudah dijaga test: 166 unit test (17 suite) dan 29 UI test lulus di 17 Pro, termasuk verdict tanpa dialog + rollback, Family mode diingat setelah relaunch, filter Activity, Disconnect/Delete, dan ganti bahasa langsung.

Semua temuan ada di ukuran teks aksesibilitas (XL) dan layar kecil (iPhone SE): titik halaman menimpa teks splash, kata terpotong di kartu mode, cincin skor Detail memenuhi layar, tombol Invite tertutup tab bar, judul empty state terpotong, dan suara VoiceOver yang belum mengikuti bahasa app. Semuanya punya jalan keluar (gulir atau ukuran teks lebih kecil), jadi P2.

Audit Xcode banyak melaporkan "Contrast failed" dan "Text clipped" yang ternyata palsu: teks yang sedang berada di bawah tab bar melayang atau bar tombol verdict ikut diburamkan efek tepi gulir iOS 26. Buktinya, elemen yang sama lulus begitu digulir ke tengah (lintasan kedua), dan screenshot menunjukkan teks utuh (lihat bagian "Catatan audit").

# Detail temuan

## P2-1 · Titik halaman menimpa teks splash di XL

P2 · Onboarding (ON-01)

Langkah: 1) iPhone SE, Settings → Accessibility → Larger Text → XL (accessibility-extra-large). 2) Buka app baru (`-UITestReset YES`). 3) Lihat slide 1.

Hasil: Indikator titik halaman (`.page(indexDisplayMode: .always)`) duduk di atas kalimat "Shoo checks the websites you open in Safari." / "Shoo memeriksa situs yang kamu buka di Safari.".

Harapan: Teks slide terbaca utuh di semua ukuran teks; titik di bawah konten.

Catatan: `SplashView` — `ScrollView` di dalam `TabView` mengisi sampai ke dasar, indikator digambar di atasnya. ID PRD ON-01.

Bukti: QA-A/P2-1_splash_titik_menimpa_teks.png — SE, ID, XL

## P2-2 · Kata terpotong di kartu mode (XL)

P2 · Onboarding (ON-03)

Langkah: 1) SE, ukuran XL, bahasa ID. 2) Buka langkah mode (`-debug.onboardingStep mode`).

Hasil: "Lindungi diriku dan keluargaku" pecah di tengah kata: "keluarga" / "ku". Kolom teks hanya selebar sisa ikon 40 pt + ikon centang.

Harapan: Kata utuh; di ukuran aksesibilitas teks mendapat lebar penuh kartu.

Catatan: `ModeCard` memakai `HStack` tetap. ID PRD ON-03.

Bukti: QA-A/P2-2_mode_kata_terpotong.png — SE, ID, XL

## P2-3 · Cincin skor Detail memenuhi layar di XL

P2 · Detail (DT-01)

Langkah: 1) SE, ukuran XL. 2) Guardian, buka Detail scan blocked (`-debug.detail …4e03`).

Hasil: Cincin 160 pt tumbuh 2× (320 pt, lebih lebar dari layar 375 pt dikurangi margin). Bersama bar tombol It's safe / Not safe yang menempel, layar pertama hanya berisi cincin + label status; link, waktu, dan bukti harus digulir jauh.

Harapan: Skor tetap besar dan terbaca, tapi link dan bukti ikut terlihat lebih cepat.

Catatan: `ScoreRing.side = size × min(textScale, 2)`. ID PRD DT-01, DT-03.

Bukti: QA-A/P2-3_detail_ring_xl.png — SE, EN, XL

## P2-4 · Tombol Invite tertutup tab bar

P2 · Shield Family (GD-03)

Langkah: 1) SE, ukuran default. 2) Guardian, Family mode On, skenario `empty` (+ banner notifikasi).

Hasil: Tombol "Invite your family" berada tepat di bawah tab bar melayang; teksnya tidak terbaca sampai layar digulir.

Harapan: Aksi utama layar kosong terlihat tanpa menggulir.

Catatan: Audit lintasan 1 menandai tombol "Contrast failed"; lintasan 2 (setelah gulir) lulus, jadi bisa dijangkau. ID PRD GD-03.

Bukti: QA-A/P2-4_invite_di_bawah_tab_bar.png — SE, EN, light

## P2-5 · Judul empty state terpotong

P2 · Activity (PR-05) / `EmptyStateView`

Langkah: 1) SE, ukuran XL, bahasa ID. 2) Protected, Activity, skenario `empty`.

Hasil: Judul "Belum ada aktivitas" tampil "Belum ada ak…". Deskripsi memakai warna `.secondary` (ditunda dari review a11y fase 04).

Harapan: Judul membungkus ke baris berikut; deskripsi `.readableSecondary` seperti layar lain.

Catatan: `ContentUnavailableView` membatasi judul satu baris. Dipakai di Activity (PR-05/GD-05) dan Family kosong (GD-03).

Bukti: QA-A/P2-5_empty_state_terpotong.png — SE, ID, XL

## P2-6 · Suara VoiceOver tidak mengikuti bahasa app

P2 · Aksesibilitas (semua layar)

Langkah: 1) iPhone dengan bahasa sistem English. 2) Profile → Bahasa Indonesia. 3) Nyalakan VoiceOver.

Hasil: (dari kode, belum didengar) Teks berbahasa Indonesia dibacakan dengan suara English karena app hanya mengganti `\.locale` SwiftUI, bukan bahasa aksesibilitas.

Harapan: VoiceOver memakai suara Indonesia saat app berbahasa Indonesia.

Catatan: Butuh perangkat fisik untuk memastikan (simulator tidak punya VoiceOver). Usulan: set `accessibilityLanguage` jendela/app mengikuti `AppSettings.language`, lalu dengar di QA-E2E (#14). Tidak diperbaiki di ronde ini karena tidak bisa diverifikasi.

Bukti: — (kode `App/RootView.swift:19`, `Features/Main/MainTabView.swift:36`)

## P3-1 · Kontras "nearly passed" untuk biru sistem dan label sekunder

P3 · Komponen (`OnboardingPrimaryButton`, `.borderedProminent`, tombol tautan, label `.readableSecondary` / `.secondary`)

Hasil: Audit: 83 "Contrast nearly passed" (EN + ID): teks putih di tombol biru sistem (Skip, Next, Continue, Turn on, Allow notifications, Invite), tautan biru "Copy link" / "Family code", label kecil "Link" / "Opened" / "Opened by" di Detail, dan deskripsi `.secondary` di kartu mode, ON-04 "Shoo is off." dan empty state. Tidak ada yang "failed" di posisi terlihat. Teks tombol tebal ≥ 17 pt termasuk teks besar WCAG (3:1), jadi lulus AA.

Catatan: Diselesaikan bersama saat re-skin (aksen lebih gelap seperti chip terpilih `#0061CC`, sekunder lewat `.readableSecondary`). Deskripsi empty state ikut diperbaiki di P2-5.

# Catatan audit

Audit `performAccessibilityAudit` (test `AccessibilityAuditUITests`, jalan atas permintaan dengan `TEST_RUNNER_SHOO_A11Y_AUDIT=1`) dicatat per layar dalam dua lintasan.

| Jenis | Jumlah (17 Pro light, EN+ID) | Kesimpulan |
| :-: | :-: | :-: |
| Contrast nearly passed | 83 | P3-1 |
| Dynamic Type partially unsupported | 66 | Palsu untuk chip/tombol toolbar: screenshot XL menunjukkan semuanya membesar; toolbar sistem dibatasi iOS |
| Contrast failed | 72 | Palsu: hanya elemen di bawah tab bar / bar verdict / tepi atas; elemen yang sama lulus setelah digulir; "Simpan nama" = tombol nonaktif (dikecualikan WCAG) |
| Text clipped | 7 | Palsu: banner notifikasi dan baris bukti tampil utuh di screenshot (A11Y_text_clipped_false_positive.png); yang nyata hanya P2-5 |
| Element has no description | 6 (ON-02, EN + ID) | Keyboard sistem (kolom nama fokus saat muncul) |
| Potentially inaccessible text | 1 (GD-01 Off) | Teks di bawah tab bar saat audit; tidak muncul lagi setelah gulir |

Di iPhone SE, audit kontras jauh lebih berisik (elemen berganti-ganti lulus/gagal antar lintasan, termasuk teks hitam di atas putih seperti "Active"), jadi kontras SE dinilai dari screenshot, bukan audit.
